# 4.4 — implementation plan

Approved-by: volodymyr · 2026-10-15

Pattern followed: `src/model_exporter/model_exporter.py` (`export_model` / `export_model_plot` — one public method per
artefact, all paths through `_get_export_path`, logging through `Logger('ModelExporter')`). ADR-003 does not add an
interface for `ModelExporter` today and this plan does not either.

## Contract changes
- boundary: `ModelExporter.export_model(model, labels, path)` unchanged; a new public method
  `export_tflite_model(model, labels, path) -> str`, called explicitly by `ExperimentSummarizeService` (after its
  DB writes) and `ModelRestorer`. Additive.
- data: new files `model.tflite` and `model_settings.json` inside the existing `<path>_<DURATION>_<af_type>` folder.
  Nothing existing is rewritten; old export folders simply lack them.
- generated output: `assets/models/**`, `assets/experiment-*/model_*` — regenerated by `.venv/bin/python main.py`
  or `export-best-model.py`; never hand-edited.

## Requirements (ordered, each independently verifiable)

### R1 — TFLite conversion in ModelExporter (S)
- files: `src/model_exporter/model_exporter.py` (change: add
  `export_tflite_model(self, model: tf.keras.Model, labels: Sequence[str], path: str) -> str`; converts with
  `tf.lite.TFLiteConverter.from_keras_model(model)`, float32, writes `model.tflite` into the export folder)
- layer: service (model_exporter)
- test: none exists in `src/` (rule P6); verified by run, see below
- executed how: one-off script in the scratchpad (export path pinned to the scratchpad, never `assets/`) builds a
  tiny Keras model with `model.input_shape` of the real feature shape, calls `export_tflite_model`, loads the file
  with `tf.lite.Interpreter`, compares with `model.predict` on random input (AC1, AC2)
- test input shape: computed by running the active `IAFStrategy` (via `AFStrategyFactory` with `sr`,
  `frame_length`, `hop_length` from `src/definitions.py`) on a synthetic `np.zeros(sr * DURATION)` signal; never
  read from `assets/` (rule P5)
- evidence: measured max abs difference printed against the 1e-4 tolerance; the `tf.lite.Interpreter`
  deprecation warning (TF 2.20 points to LiteRT) is recorded, not hidden, and no `ai-edge-litert` dependency is
  added (rule C2)
- risk: Keras 3.10 + TF 2.20 `from_keras_model` path — see Risks

### R1b — Failure handling (S) — lands in the same commit as R2, because it writes both files
- files: `src/model_exporter/model_exporter.py` (change: wrap the conversion, log through `self.loger`, re-raise;
  one rule: convert first, then write BOTH `model.tflite.tmp` and `model_settings.json.tmp`, and only when both
  are written `os.replace` them into place. On any failure, remove the temp files AND any `model.tflite` /
  `model_settings.json` already in that folder, so a stale previous-step file can never sit beside the new
  SavedModel; then re-raise)
- layer: service
- executed how: two failure runs in the scratchpad, a patched converter that raises: (a) fresh export folder,
  (b) export folder that already holds an old `model.tflite` and `model_settings.json`. Each shows the log line,
  the raised error, and the folder listing with neither file present (AC5). A third run makes the JSON write
  fail after the converter succeeded and shows the same empty result.
- evidence: the failure output and the three directory listings
- risk: none

### R2 — Settings sidecar (S)
- files: `src/model_exporter/model_exporter.py` (change: write `model_settings.json` with `labels`, `af_type`
  (`self.af_strategy.AFType.value`), `duration` (`str(DURATION)`) — same values as `ModelInstance.get_settings` —
  and `input_shape` (`list(model.input_shape[1:])`) because the `.tflite` takes the raw Keras input)
- layer: service
- executed how: same script; reload the SavedModel and compare `af_type` / `duration` against
  `signatures['get_settings']` and `labels` against `label_names` from `__call__`; run once with `labels` as a
  numpy array and once as a list, both must serialise as a list of str (AC3)
- evidence: the JSON file next to the reloaded SavedModel values
- risk: none

### R3 — Wire into the callers (S)
- files: `src/experiment/experiment_summarize_service/expirement_summarize_service.py` (change: one call to
  `export_tflite_model` after `save_training_history_plot`, inside the `EMULATE_MODE is False` block, so DB writes
  are already committed); `src/model_restorer/model_restorer.py` (change: one call after `export_model`)
- layer: orchestration (experiment) and service (model_restorer)
- executed how: scratchpad script calls `export_model` then `export_tflite_model` with the tiny model (path in the
  scratchpad) and checks SavedModel + `.tflite` + JSON all land and `load_model` / `get_settings` still work
  (AC1, AC4). The call order in `summarize` (AC6) is shown by reading the changed lines; the full pipeline run is
  not executed (Q5) and goes under "Not verified".
- evidence: listing of the export folder; `git diff` of the two call sites
- risk: a conversion failure aborts the grid loop at that step (nothing in `Experiments.run` catches), but the
  Postgres writes and the SavedModel are already done; see Risks

## Risks
| Risk | Impact | Cheapest way to find out early |
|------|--------|-------------------------------|
| `from_keras_model` fails or yields different output under Keras 3.10 / TF 2.20 | R1 blocked; may need `from_concrete_functions` on `ModelInstance.__call__` instead | run R1's script first, before touching `export_model` |
| Device runtime needs the string outputs (`class_names`) or Select TF ops that the SavedModel path provided | `.tflite` is unusable on device as planned (open questions 2, 3) | ask the maintainer; convert `ModelInstance.__call__` with builtin ops only and read the converter error |
| A model that will not convert aborts the grid at that step: R1b re-raises and `Experiments.run` has no try/except, so `experiment.finish()` is skipped and a rerun redoes the step | lost time, no lost data: SavedModel and DB rows are written before the TFLite call (Q4, option A) | R1b failure run; the raised error names the model path |
| The real pipeline run is not executed (Q5) | R3 wiring is only read, not run | the maintainer runs `main.py` / `export-best-model.py` on their own `assets/` after backing it up |

## Assumptions
- TFLite sits beside the SavedModel; nothing existing is removed (open question 1).
- float32, builtin ops, no quantization — goal 1 outranks goal 3 until accuracy is measured.
- Numeric output only in the `.tflite`; labels and settings travel in the sidecar JSON.
- Branch `feat/4.4-tflite-export`, created at implementation time, not now.
- Complexity: R1 S, R1b S, R2 S, R3 S.
- Q1–Q5 are decided in `spec.md` (maintainer, 2026-10-15).
- Path convention: new paths go through `self.files` / `_get_export_path` like the rest of the module; temp-file
  rename uses `os.replace`; `export_tflite_model` creates the export folder itself, as `export_model_plot` does.
- Python 3.9: `Optional[...]` / `List[...]` type hints, not `X | None`.
